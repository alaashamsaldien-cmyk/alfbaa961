# تنسيب المدارس والمتابعة

النسخة المحلية؛ لم تُطبق ترقية قاعدة الإنتاج ولم تُنشر.

- مدارس الخريطة المعتمدة: اختيار حتى 500 مدرسة، ثم منسّق أو أكثر.
- مشترك: إضافة المختارين مع الحفاظ على الحاليين، أو استبدال الجميع، أو إزالة المختارين فقط.
- منفصل: توزيع بالتناوب حسب ترتيب اختيار المنسقين، واستبدال التنسيب السابق. معاينة كل مدرسة قبل الحفظ.
- سجل قبل/بعد مع المدير والتوقيت ضمن معاملة الحفظ. الحفظ يرفض المعاينة التي تغيّرت بياناتها.
- الحساب غير المنسّب لا يستطيع الوصول للمدرسة حتى عبر البحث أو رابط مباشر.
- تعطيل الحساب يبقي تكليفاته وتاريخه محفوظين، ويمنع الدخول. يمكن استبدال تكليفه من التنسيب.
- الزيارة الميدانية تظهر بعلامة مشتركة؛ الإنجاز الشخصي حسب المنفذ. التواصل ليس زيارة ميدانية.
- قوائم الموبايل تتحدث كل 30 ثانية أثناء فتح الصفحة وعند الرجوع إليها.
- مواعيد «ناوي أزورها» والمتابعة مشتركة للرؤية، والإلغاء/الإنهاء للمنفذ أو الإدارة.
- التذكير داخل النظام: المدارس المستحقة أعلى القائمة وبشارة حان موعد المتابعة. لا إشعارات دفع خارج المتصفح ولا SMS.
- البلاغ لا يغيّر الموقع ولا يحذف المدرسة. الإدارة تراجعه من تفاصيل المدرسة ثم تصحح البيانات إن لزم.

## النشر المؤجل
قبل نشر التطبيق، تطبيق ملف `prisma/manual-migrations/20261116-school-assignments.sql` على قاعدة الهدف بعد موافقة النشر. الملف إضافي، وينقل التنسيبات القديمة إلى جدول الربط، ولا يحذف المدارس أو الزيارات. لا تستخدم `db:push --accept-data-loss`.
أبقينا الحقل القديم لدعم التنسيب السابق؛ بعد نشر الجديد، يجب أن تمر تغييرات التنسيب عبر نافذة التنسيب الجديدة.

## التحقق
`tsc --noEmit --incremental false` واختبارات `scripts/assignment-workflow-tests.mjs` على قاعدة محلية مؤقتة فقط (يرفض الاختبار أي مضيف غير عنوان الاختبار المحلي). لا تستخدم بيانات حسابات حقيقية للاختبار.
